# schemacheck-rules: provider tool-schema rulebook (task #7)
Written by researcher-5, an autonomous AI agent (Claude) at Kiln, 2026-11-13. Sources were fetched via sub-agents; the "Q-grade" column says how solid each quote is:
- **V** = verbatim from the page text as fetched; **S** = the fetch tool returned only a model summary for that part of the page (wording NOT verified; re-check before shipping the rule's message text); **I** = verbatim from a GitHub issue/PR (real failing case).
Doc URLs: OpenAI pages are at developers.openai.com (platform.openai.com 301s there). Gemini ai.google.dev 301s to aistudio.google.com/docs/...; Anthropic docs.claude.com 302s to platform.claude.com. Cite the final URLs below (the redirect source also works for users).

## 1. OpenAI strict (Structured Outputs / strict function calling)
Base: SO = https://developers.openai.com/api/docs/guides/structured-outputs ; FC = https://developers.openai.com/api/docs/guides/function-calling
| ID | Rule | Sev | Source | Quote | Q | Autofix |
|---|---|---|---|---|---|---|
| OAI001 | Every object needs `additionalProperties: false` | error | SO, FC | "we require developers to set `additionalProperties: false` to opt into Structured Outputs." / FC: "`additionalProperties` must be set to `false` for each object in the `parameters`." | V | Yes: set `additionalProperties:false` on every object schema (also inside $defs, anyOf branches, items). If it was a schema/true, change to false and note data loss (schema-valued additionalProperties = free-form map; report as unfixable-lossy, see §3). |
| OAI002 | All keys in `properties` must be in `required` | error | SO, FC | SO: "To use Structured Outputs, all fields or function parameters must be specified as `required`." FC: "All fields in `properties` must be marked as `required`." | V | Yes: `required = list(properties)` (keep order). Fields that were optional become nullable first (OAI003 transform) so semantics are kept. |
| OAI003 | Optional fields are expressed as a union with null | info/advice for OAI002 fix | SO, FC | SO: "it is possible to emulate an optional parameter by using a union type with `null`." FC: "You can denote optional fields by adding `null` as a `type` option" | V | Yes: for a property not in `required`: `type:"string"` -> `type:["string","null"]`; for `enum`, add `null` to enum values; for `anyOf`/`$ref`-only props wrap `anyOf:[orig,{"type":"null"}]`. |
| OAI004 | Root must be an object and must not be `anyOf` | error | SO | "Note that the root level object of a schema must be an object, and not use `anyOf`." | V | No (unfixable; report). Possible: if root is anyOf of objects, user must restructure. |
| OAI005 | Unsupported composition keywords: allOf, not, dependentRequired, dependentSchemas, if/then/else | error | SO | Heading "Some type-specific keywords are not yet supported"; list: "`allOf`, `not`, `dependentRequired`, `dependentSchemas`, `if`, `then`, `else`"; also "call the API with an unsupported JSON Schema, you will receive an error." | V | allOf: yes when branches are plain objects with no conflicting keys (merge properties/required, recursively). others: unfixable. |
| OAI006 | `$ref` / `$defs` ARE supported incl. recursion (`#`) | ok (no rule) | SO | "You can use definitions to define subschemas which are referenced throughout your schema." "Recursive schemas are supported." | V | n/a. Do NOT flag $ref for OpenAI. But see OAI007. |

Inline is safest (also needed for Gemini). |
| OAI008 | Limits: max 5000 properties total, 10 nesting levels; 1000 enum values; enum/const/property-name chars <=120,000 | error | SO | "A schema may have up to 5000 object properties total, with up to 10 levels of nesting." | OAI009 | `format` supported values (strings): date-time, time, date, duration, email, hostname, ipv4, ipv6, uuid; also pattern, min/max, multipleOf, minItems/maxItems | ok; unlisted formats are UNVERIFIED | SO | "`format` — Predefined formats for strings. Currently supported:" then list. | V | If format not in list (e.g. `uri`): strip it and put the format into `description` (warning-level; whether OpenAI rejects unlisted formats is UNVERIFIED). |
| OAI010 | Fine-tuned models additionally reject minLength/maxLength/pattern/format, minimum/maximum/multipleOf, patternProperties, minItems/maxItems | error (ft models only) | SO | "For fine-tuned models, we additionally do not support the following:" | V | Opt-in profile flag later; out of MVP. |

| OAI012 | `$schema` not mentioned in SO/FC | UNVERIFIED | - | not found | - | Strip is harmless; see common form. |

## 4. Common-denominator form (passes OpenAI strict + Gemini + Anthropic strict, as far as verified)
```
{
 "type":"object",
 "properties": { "a": {"type":"string","description":"..."},   // required field
                 "b": {"type":"string","nullable":true,"description":"..."} }, // optional -> see below
 "required": ["a","b"],            // OpenAI: ALL keys required
 "additionalProperties": false
}
```
Rules: (1) no `$schema`, `$id`, `title`-only noise; no `$ref`/`$defs` (inline); (2) every object has `additionalProperties:false` AND `required` = all keys (OpenAI+Anthropic strict); (3) no `const`; (4) `enum` only on string type; (5) no `oneOf`/`allOf`/`not`/`if`; avoid `anyOf` except nullable; (6) `format` only from the intersection: date-time, date, time, email, hostname, ipv4, ipv6, uuid, duration (OpenAI list, V; Anthropic adds `uri`); (7) drop min/max/length keywords (move to description) for max portability; (8) root is an object, not anyOf.
**Conflicts / no single form:**
- **Optional fields**: OpenAI says use `type:["string","null"]` (V). Gemini `parameters` Schema uses `nullable:true` (V) and a single-value `type` enum; type arrays in Gemini function declarations are UNVERIFIED (docs summary says OK for structured-output mode). Both `{"type":["string","null"],"nullable":true}` in one schema: UNVERIFIED if OpenAI accepts unknown `nullable` (not documented) and if Gemini accepts the type array. Recommendation: --fix emits per-target forms: `--profile all` emits type-array null form (OpenAI/Anthropic) and warns that Gemini `parameters` may need `nullable`; profile gemini alone emits `nullable:true`. Need a live-API check to settle (cannot do offline, out of scope) -> UNVERIFIED.
- **additionalProperties:false vs Gemini**: OpenAI requires it, Gemini's `parameters` field list omits it (livekit workaround strips it). Conflict unresolved: with `all`, keep it and warn GEM006.
- **Schema-valued additionalProperties / free-form maps** (`additionalProperties:{...}`, `patternProperties`): OpenAI requires false -> unfixable; report only.
- **Recursion**: OpenAI/Anthropic-strict ok-ish ($ref #), Gemini function path rejects $ref -> unfixable for recursive schemas.
- **anyOf unions of different types**: unfixable cross-provider; lossy "pick first" only with `--lossy`.
